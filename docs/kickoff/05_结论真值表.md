状态：**开发契约 v0.1。** 正式发布需由业务负责人和独立复核者确认，并同步主方案 Finding/Coverage Schema。

## 规则级结论

| 条件 | 结果 | 必须保留的证据/约束 |
|---|---|---|
| 规则适用；所有必要支持证据可靠；Coverage COMPLETE；谓词成立 | PASS | 适用依据、全部必要Evidence、Fact、计算过程、规则版本 |
| 已获得足以推翻规则的可靠反例；相关例外已排除 | FAIL | 反例Evidence、政策来源、规则版本；不要求其他无关规则已完成 |
| 必需附件义务明确；Material Manifest已冻结；所有候选来源检查完成；附件确认不存在 | FAIL | 完整清单、分类完成记录、缺失证书 |
| 上传未完成、文件损坏、未分类或候选来源尚未查完 | NEED_HUMAN_REVIEW | 未完成范围、失败文件、剩余动作；不得假装“缺失” |
| 关键值、单位、表头、标题或姓名不可可靠读取 | NEED_HUMAN_REVIEW | 不确定字段、候选值、Grounding状态 |
| 规则适用性或例外关系无法确定 | NEED_HUMAN_REVIEW | 未决适用性项必须进入账本并阻断整包自动通过 |
| 有可靠证据明确不适用 | NOT_APPLICABLE | 不适用条件与来源；不得统计为PASS |
| 政策只是非强制建议 | WARNING | 保持建议性质，不升级为违规 |
| 运行时/解析器故障，恢复预算耗尽且无法完成业务判断 | SYSTEM_ERROR | 故障原因、重试/恢复记录；不得转成材料违规 |

## 项目级聚合

项目级“可自动通过本次形式审查”必须同时满足：

1. 所有本批已发布且适用的规则都进入终态；
2. 不存在 `FAIL`、`NEED_HUMAN_REVIEW`、`SYSTEM_ERROR`；
3. Coverage Ledger 中没有未决适用性；
4. `NOT_APPLICABLE` 有依据但不计为PASS；
5. 未自动化条款已明确转人工或不在支持范围，不能从账本静默消失。

项目级聚合参考：

| 规则集合状态 | 项目级状态 |
|---|---|
| 至少1条FAIL | FAIL |
| 无FAIL，但至少1条HUMAN | NEED_HUMAN_REVIEW |
| 无FAIL/HUMAN，但存在SYSTEM_ERROR | SYSTEM_ERROR |
| 所有适用规则PASS，其他规则均有可靠N/A，且Coverage完整 | PASS |
| 存在WARNING但其余条件满足 | PASS_WITH_WARNING（若API不支持该枚举，则项目PASS并单列warnings） |
