## 2. 技术选型与模块边界

| 层 | 选型 | 边界说明 |
|---|---|---|
| 任务 | 同步执行并持久化 | 无队列。先 commit「运行中」任务和逐项占位，再跑 RULE-007；刷新可看到进行中条目，结束后写终态 |
| RULE-007 | 复用 `run_funding_review` | 不重写金额提取；不写入 `rules` 表 |
| 勾选规则 | 当时版本快照 | GET `/api/rules` 已启用规则；本分支无执行器，一律「未执行」 |
| RULE-005 | 绑定展示 | **不**按经费上限判 PASS/FAIL；缺类别不判 FAIL |
| 表结构 | SQLite `create_all` 补表 | 不引入迁移框架 |
| 旧入口 | 保留 | 「开始核对」与 `POST /api/projects/{id}/funding-review` 仍可用 |

状态映射：

| 经费核对 / 条目来源 | 工作台条目状态 |
|---|---|
| 任务已落库、RULE-007 尚未跑完 | 执行中 |
| PASS / FAIL | 已完成（带核对结论；规则 FAIL ≠ 任务失败） |
| NEED_HUMAN_REVIEW | 待确认 |
| SYSTEM_ERROR | 失败 |
| 无执行器的勾选规则 | 未执行 |

关键模块：

- 审查 API：`backend/app/api/reviews.py`
- 审查服务：`backend/app/services/reviews.py`
- 模型：`ReviewTask` / `ReviewItem`（`backend/app/models.py`）
- 前端：`frontend/src/ReviewWorkspace.tsx`

## 3. 已实现 API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/projects/{id}/reviews` | 创建任务：内置 RULE-007 + `rule_ids` 中已启用规则 |
| GET | `/api/projects/{id}/reviews` | 任务列表（新到旧，含逐项） |
| GET | `/api/projects/{id}/reviews/{task_id}` | 指定任务 |
| POST | `/api/projects/{id}/funding-review` | 保留；工作台内部复用同一服务 |

未启用规则 → 400「规则未启用，不能纳入本次审查」。未知规则 → 404。需要 JSON body（`{}` 或 `{ "rule_ids": [] }`）；空 `rule_ids` 仍只跑 RULE-007。

## 6. 产品口径（联调勿误解）

- 工作台是新入口；「开始核对」仍是 B03 单独经费核对，不要删。
- 「未执行」表示本分支没有该规则的执行器，不是任务失败。
- RULE-007 的 FAIL（金额不一致）是已完成条目的核对结论，任务仍为已完成。
- 勾选 RULE-005 只绑定当时版本快照，**不**按学科类别上限判 PASS/FAIL（B08）。
- RULE-007 是程序内置核对，不是 `rules` 表中可停用的一行。

## 7. Review 最小修复

| 项 | 处理 |
|---|---|
| 空 RUNNING 行随即 COMPLETED，刷新看不到进度 | 先 commit 带条目的运行中任务；RULE-007 为执行中，勾选规则为未执行；刷新可续看 |

| 记录把实现选择写成验收通过 | 验收表只保留八周计划四句；其余列入实现选择 |

## 8. 已知限制

- 本分支仍是同步请求，无后台队列、重试、取消（B17）；运行中状态靠第一次 commit，不轮询。
- 仅 RULE-007 有执行器；GET `/api/rules` 勾选规则一律未执行。
- RULE-005 不做 PKG 学科类别 PASS/FAIL（B08）。
- 项目列表卡片仍写「尚未审查」（列表接口无任务摘要，不在本分支改契约）。
- 无登录权限。
