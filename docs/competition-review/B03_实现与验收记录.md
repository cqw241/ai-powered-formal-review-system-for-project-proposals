## 2. 技术选型与模块边界

| 层 | 选型 | 边界说明 |
|---|---|---|
| 提取 | 原生 PDF 文本优先；LLM 视觉可选回退 | 数字 PDF 用确定性解析 + `search_for` 定位；文本不足时可走云端视觉 |
| 计算 | 程序侧单位换算与差额 | 不执行模型返回的任意代码；未知值不当作 0 |
| 规则 | 手工 RULE-007 | 只比较「申请经费/申请总额」，不与「项目总经费」混淆 |
| 持久化 | SQLite `funding_reviews` | 每次核对追加一条；GET 返回最新 |

关键模块：

- `backend/app/services/money.py` — 单位换算
- `backend/app/services/funding_extract.py` — 字段提取与 bbox
- `backend/app/services/funding_review.py` — 比较与落库
- `backend/app/api/funding.py` — REST
- 前端问题卡：`frontend/src/App.tsx`

## 3. 已实现 API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/projects/{id}/funding-review` | 提取两侧申请经费、换算、比较并持久化；201 |
| GET | `/api/projects/{id}/funding-review` | 最新结果；无则 404 |

问题卡字段：`check_field`、两侧原始值、规范化金额/单位、差额、状态、原因、页码与 bbox。

状态：`PASS` / `FAIL` / `NEED_HUMAN_REVIEW` / `SYSTEM_ERROR`。

## 7. 已知限制

- 提取以原生文本为主；扫描件需配置 LLM 才会尝试视觉回退，否则待确认。
- 扫描件高亮依赖模型给出可用的归一化 `BBOX`；未给出则仍可能只有页码、无高亮框。
- 高亮基于 PDF 页面坐标系百分比叠加，依赖页图与页面矩形一致。
- 无材料版本管理：重复上传同类材料时取最新 READY 件比较。
- 未实现完整审查工作台、政策规则或重审对比。
