## 2. 技术选型与模块边界

| 层 | 选型 | 边界说明 |
|---|---|---|
| 候选 | 仍是草稿 | 启用才从 FUNDING_CAP 快照生成 Rule + RuleVersion（`rule_code=RULE-005`） |
| 版本 | 追加 `rule_versions` | 编辑已启用规则只新增版本，不改历史行；停用不删版本 |
| 审查绑定 | 复用 POST `/api/projects/{id}/funding-review` | 每次运行把当时已启用规则的当前版本写入该次 `bound_rules` |
| RULE-005 | 绑定展示 | 不按项目学科类别裁决；缺类别不判 FAIL；RULE-007 行为不变 |
| 表结构 | SQLite `create_all` 补表 | 不引入迁移框架 |

关键模块：

- 规则 API：`backend/app/api/rules.py`
- 规则服务：`backend/app/services/rules.py`
- 模型：`Rule` / `RuleVersion`（`backend/app/models.py`）
- 经费核对绑定：`backend/app/services/funding_review.py`
- 前端：`frontend/src/PolicyWorkspace.tsx`、项目详情绑定卡（`frontend/src/App.tsx`）

## 3. 已实现 API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/policies/{id}/candidates/{id}/enable` | 仅 FUNDING_CAP；生成或重新启用 RULE-005 |
| GET | `/api/rules` | 规则列表（含版本） |
| GET | `/api/rules/{id}` | 规则详情 |
| PATCH | `/api/rules/{id}` | 新增版本；金额未知保持 `null`（不当 0） |
| POST | `/api/rules/{id}/disable` | `enabled=false` |
| POST | `/api/rules/{id}/enable` | 重新启用，不新增版本 |
| POST | `/api/projects/{id}/funding-review` | RULE-007 + 当时启用规则快照 |
| GET | `/api/projects/{id}/funding-review` | 最新核对 |
| GET | `/api/projects/{id}/funding-reviews` | 历史核对（含各自 `bound_rules`） |
| GET | `/api/projects/{id}/funding-reviews/{review_id}` | 指定一次核对的当时快照 |

规则字段：名称、政策出处、类别、比较对象（申请经费）、要求（comparator + amount_yuan）。

`GET /api/policies/{id}` 的候选带 `rule`（启用状态与当前版本号）。

3. 刷新页面：仍显示已启用 RULE-005 v2。
4. 新建项目，上传 A1 申报书与 A2 预算表，开始核对：RULE-007 一致；绑定卡显示 RULE-005 v2 / 280000 元 / 申请经费对照 300000 元。
5. 停用该规则后再核对：新结果 `bound_rules` 为空；点开历史核对，旧结果仍含 v2。

## 6. 已知限制

- 仅 FUNDING_CAP 可启为 RULE-005；通用条款候选仍是草稿。
- RULE-005 在本分支只做绑定展示，不做 PKG 学科类别 PASS/FAIL（留给 B08）。
- RULE-007 仍是程序内置核对，不是 `rules` 表中的一条可停用规则。
- 无规则删除；停用后版本保留。
- 审查工作台（选择规则、任务进度）留给 B06。
