## 3. 已实现 API / 配置

### API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/policies` | multipart：`file`；同步解析 PDF、提取候选 → `READY`/`FAILED` |
| GET | `/api/policies` | 政策列表（含 `candidate_count`） |
| GET | `/api/policies/{id}` | 详情 + 候选列表 |
| GET | `/api/policies/{id}/pages/{page}/text` | 页原生文本 |
| GET | `/api/policies/{id}/pages/{page}/image` | 页 PNG |
| PATCH | `/api/policies/{id}/candidates/{candidate_id}` | 编辑草稿字段并持久化 |

候选关键字段：`kind`、`title`、`category`、`amount_raw`、`amount_yuan`、`amount_unit`、`comparator`、`source_clause`、`source_page`、`source_quote`。

经费上限类：`kind=FUNDING_CAP`；金额未知时 `amount_yuan=null`（不当作 0）。

### 配置

见 `.env.example`：新增 `POLICIES_DIR`（默认 `./backend/data/policies`）。上传大小仍受 `UPLOAD_MAX_BYTES` 约束。

## 6. Review 最小修复（开 PR 前）

| 项 | 处理 |
|---|---|
| 无金额条款卡片显示「规范化：未知（非 0）」 | 仅经费上限或确有金额字段时展示规范化；通用条款不再套用金额未知口径 |
| 经费上限在文中无 P-05 时仍写 `source_clause=P-05` | 仅当原文含 `P-05` 才写入来源条款，否则为 `null` |

## 7. 已知限制

- 候选提取以原生文本确定性规则为主；扫描件/无文本 PDF 不会自动走视觉提取（本分支未接 LLM 政策提取）。
- 候选是草稿，不能启用进审查；B05 再做规则编辑与版本。
- 无政策删除/替换；重复上传会产生多份政策记录。
- 通用条款候选（P-01…P-10 除 P-05）仅作草稿展示，不含结构化金额字段。
- 经费上限金额无法解析时规范化为「未知（非 0）」，不会写成 0；无金额的条款候选不显示该文案。
