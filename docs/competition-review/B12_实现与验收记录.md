## 2. 设计

- 机器结果仍写入 `review_item_results`，任务完成后不再改写。
- 人工处置追加 `human_decisions`（操作、字段原值/新值、操作者、说明、时间、受影响规则）。
- 有效结果写入 `review_item_human_results`，并同步工作台 `ReviewItem.status/check_status/summary`。
- `CORRECT_FIELD` 按字段映射重跑现有执行器：负责人 → RULE-003；申请经费/申请总额 → RULE-007/005，预算侧再加 RULE-006。
- 确认问题不改机器结论，条目变为已完成；标记不适用把有效结论改为 `NOT_APPLICABLE`，原文证据保留给 B11 对照。
- 对照原文继续用有效结果的 `ReviewEvidence`，扫描页高亮路径不变。

## 3. 已实现 API

| 方法 | 路径 | 行为 |
|---|---|---|
| POST | `/api/projects/{id}/reviews/{task_id}/items/{item_id}/human-decisions` | `CONFIRM` / `CORRECT_FIELD` / `MARK_NOT_APPLICABLE`；返回整单任务 |

请求需填写 `operator` 与 `note`。修正字段还需 `field_name`、`material_id`、`corrected_value`。金额无法解析时 400，不写记录。

任务条目增加 `original_result`（机器原结果）与 `human_decisions`（可追溯历史）。`result` / `compare` 展示当前有效结果。
