## 2026-09-10 补充：pi-telemetry接入判断

- 【联网核验】Pi v0.85.1的[pi-agent-core](https://github.com/earendil-works/pi/blob/v0.85.1/packages/agent/package.json)和[pi-ai](https://github.com/earendil-works/pi/blob/v0.85.1/packages/ai/package.json)均声明对`@earendil-works/pi-telemetry`的依赖。当前没有代码，不能称项目已经安装或启用。
- 【联网核验】[固定版本说明](https://github.com/earendil-works/pi/tree/v0.85.1/packages/telemetry)提供显式Context/Span契约、NOOP、内存参考实现、类型Schema和适配器一致性测试；不包含Exporter或监控后端。内存实现无时间戳、存储无界，仅适合按任务/测试隔离使用。
- 【建议，待实施】纳入Pi适配层的轻量遥测接入，优先级P1；首周定义业务ID关联与可关闭接口。若直接import该包，显式锁定直接依赖并提交锁文件，不依赖传递依赖提升。无需新增大型监控平台。
- 【建议】先覆盖审查、取证、验证、模型调用/工具调用等阶段；自有本地适配器使用单调时钟计时、有限缓冲、脱敏、异步导出和故障隔离。默认不采集正文、Prompt、模型全文或工具完整参数；未知usage标记不可用，不计为0；重试和工具内部模型调用不能漏记或双计。
- 【建议】Telemetry只用于诊断；Finding/Evidence/规则发布/人工改判继续通过业务数据库与审计事务留存，不能因遥测失败丢失业务审计。队列传可序列化关联ID，不持久化Context/Span对象。
- 【联网核验】[AgentOptions源码](https://github.com/earendil-works/pi/blob/v0.85.1/packages/agent/src/agent.ts)没有简单的Agent级telemetryContext配置项；应在运行时适配、streamFn/provider options与领域工具边界显式接入，不能承诺安装后自动获得完整调用链。
- 【验收建议】官方适配器一致性用例；关闭/故障时业务结果与异常保持不变且回调仅执行一次；并发任务不串链；计时及usage与网关记录对齐；无正文泄露；长任务缓冲有界。收益中高，基础接入估计2—3开发人日，纳入现有可观测性预算，不增加既定400人日容量。
- 此判断细化上一轮可观测性建议，不改变“业务核心不依赖Pi运行时类型”和“遥测组件不是核心创新点”的结论；未安装依赖、未修改原参赛方案。
